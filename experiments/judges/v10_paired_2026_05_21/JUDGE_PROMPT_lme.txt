# Input format

The input file contains `items: [...]`. Each item has:

- `anonymous_id`: an opaque identifier of the form `lme_item_NNNN`.
- `qtype`: one of `single-session-user`, `single-session-assistant`, `multi-session`, `single-session-preference`, `temporal-reasoning`, `knowledge-update`. Items whose `qid` field ends with `_abs` should be treated as abstention questions regardless of qtype.
- `question`: the user question.
- `gold`: for most qtypes this is the correct answer. For `single-session-preference` this is a rubric describing what a good personalized response looks like.
- `response`: the model-generated response to be judged (may be truncated to roughly 500 characters).
- `qid`: an opaque identifier (used to detect `_abs` abstention items).

# Rubrics

Quoted verbatim from the official LongMemEval evaluation script (Wu et al., ICLR 2025, https://github.com/xiaowu0162/longmemeval, file `src/evaluation/evaluate_qa.py`). Do not deviate from these rubrics.

## (a) single-session-user, single-session-assistant, multi-session

> I will give you a question, a correct answer, and a response from a model. Please answer yes if the response contains the correct answer. Otherwise, answer no. If the response is equivalent to the correct answer or contains all the intermediate steps to get the correct answer, you should also answer yes. If the response only contains a subset of the information required by the answer, answer no.

## (b) temporal-reasoning

> [same as (a)] In addition, do not penalize off-by-one errors for the number of days. If the question asks for the number of days/weeks/months, etc., and the model makes off-by-one errors (e.g., predicting 19 days when the answer is 18), the model's response is still correct.

## (c) knowledge-update

> I will give you a question, a correct answer, and a response from a model. Please answer yes if the response contains the correct answer. Otherwise, answer no. If the response contains some previous information along with an updated answer, the response should be considered as correct as long as the updated answer is the required answer.

## (d) single-session-preference

> I will give you a question, a rubric for desired personalized response, and a response from a model. Please answer yes if the response satisfies the desired response. Otherwise, answer no. The model does not need to reflect all the points in the rubric. The response is correct as long as it recalls and utilizes the user's personal information correctly.

## (e) abstention (qid ends with `_abs`)

> I will give you an unanswerable question, an explanation, and a response from a model. Please answer yes if the model correctly identifies the question as unanswerable. The model could say that the information is incomplete, or some other information is given but the asked information is not.

# Judgment rules

- Apply the rubric for the item's `qtype` (or `abstention` if `qid` ends with `_abs`) strictly but fairly. Do not invent additional criteria.
- If the response is a hallucinated continuation that fabricates a "User:" or "Assistant:" turn supplying the correct answer after the model's own answer refused, do not credit it — the model's actual answer to the question is what matters.
- Equivalent phrasings count as `true` (e.g., "two appointments" equals "2 appointments").
- For preference questions: `true` only when the response uses concrete user-specific details (named items, prior trips, owned gear, named contacts, specific recipes, etc.). Generic recommendations that happen to overlap by chance are `false`.
- For abstention items: `true` if the model declines or says the requested information is not available; `false` if it fabricates a specific wrong answer, even if it later partially acknowledges uncertainty.
- Process all items. Do not skip any.
- Be deterministic: same input → same output. Do not introduce randomness.
